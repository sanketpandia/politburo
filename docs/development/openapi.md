# Local OpenAPI workflow

## Source of truth

`api/openapi/politburo.yaml` is the authoritative **machine** API contract
(JSON under `/health/*` and `/api/v1/...`). Do not put SSR HTML routes in
OpenAPI. Do not maintain a separate hand-written Politburo schema in Comrade Bot
or Labour Bureau.

The contract has three local consumers:

| Consumer | Input | Output |
|---|---|---|
| Politburo Go server | `api/openapi/politburo.yaml` | `internal/api/generated/politburo/server.gen.go` |
| Swagger UI | Bind-mounted authoritative YAML | Read-only viewer on `http://localhost:8081` |
| Comrade Bot | Synchronized copy of the authoritative YAML | `src/generated/politburo-api.ts` |

Generated Go files are build artifacts: they are ignored by Git and must not be
edited manually. Local builds should run `make generate`; CI and both container
builds generate them before compiling.

## Editing the API

From `politburo/`:

```sh
# Edit api/openapi/politburo.yaml, then regenerate Go bindings.
make generate-api

# Verify that generation succeeds.
make generate-check

# Generate Go bindings and start the local Swagger viewer.
make openapi-view
```

Open `http://localhost:8081`. The YAML is bind-mounted, so subsequent contract
edits require only a browser refresh. Stop the viewer with:

```sh
make openapi-stop
```

The Compose service retains the historical name `swagger-editor`, but it runs a
pinned, read-only Swagger UI image. Contract changes belong in the source YAML,
not in the browser.

## Updating Comrade Bot (local sibling layout)

When Comrade Bot adds OpenAPI sync scripts, run them after changing the Politburo
contract. Until then, update bot HTTP calls in `src/services/apiService.ts` to
match new `/api/v1` routes.

Planned workflow (from `comrade-bot/` when scripts land):

```sh
npm run api:generate
npm run api:check
npm run build
```

`api:generate` would copy `../politburo/api/openapi/politburo.yaml` into the
bot repo and emit typed `paths` / `operations` / `components` under
`src/generated/`.

Exercise the rewrite locally by pointing the bot at Politburo's default port:

```sh
API_URL=http://localhost:8082 npm run dev
```

The bot reads `comrade-bot/.env` and defaults to `http://localhost:8080`; set
`API_URL=http://localhost:8082` when testing against the rewrite. Local dev runs
the bot on the host via `start-dev.sh`, not in Compose.

## Infinite Flight client contract

The upstream Infinite Flight contract is kept separate under
`api/openapi/infinite-flight/`. Request operations, reusable responses, and
schemas live in their own folders, and generation writes only to
`internal/api/generated/infiniteflight/`.

```sh
make generate-infinite-flight-api
```

`make generate` and `make generate-check` cover both the Politburo server
bindings and the Infinite Flight client.

## Recommended contract-change sequence

1. Change `politburo/api/openapi/politburo.yaml`.
2. Run `make generate-api` and the Go tests from `politburo/`.
3. View the contract with `make openapi-view`.
4. Update Comrade Bot handlers or run `npm run api:generate` when that script exists.
5. Commit source contracts and any bot-side generated output; Politburo's ignored Go
   output is regenerated by CI and container builds.
